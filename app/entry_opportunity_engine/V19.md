# Entry Opportunity 19: protect Core buy advances

MarketBot 7.64.0 selects Entry Opportunity 19.0.0, embedded strategy 19.0.0.
Profit protection rule 1.0.0 applies to LONG Core Entry / Core Recovery L1-L4
checkpoints and their matching open horizon legs. Reference checkpoints,
SwingTrade, countertrend and SHORT keep their existing exit policies.

Initial R is entry price minus that entry's original invalidation. On each
final regular-session 1-minute bar, evaluate the already-active stop/target
first. If still open and the close is at least entry + R, raise protection to
max(previous protection, entry, close - R). Never lower it. The new stop is
effective on subsequent bars, not earlier within its triggering candle.
Use closes rather than wick highs. This trails continuously from +1R, without
a discontinuity at +2R. Original invalidation and objective stay immutable;
no objective from another thesis is introduced.

Open gaps fill at the open, which can be worse than the protection level and
can still produce a loss. If OHLC spans both active protection and target,
stop first unless the open already satisfies the target. Exit excursions use
only previously observed extrema, open and fill. No commissions/slippage are
modeled. This is analytical paper tracking, not broker stop-order placement.

Protection fields and evidence-bar timestamp persist in checkpoint/leg JSON.
Repeated or older market bars do not re-arm or change a completed exit.
Legacy open records start observing new closes; their historical MFE does not
retroactively activate protection. Existing closed history remains unchanged.
The evidence timestamp identifies the beginning of the completed minute bar;
the decision is only available after that bar closes.

Each stop increase emits `profit_protection_updated` on the existing Entry
Opportunity event flow, carrying the updated checkpoint. Exit events identify
`core_entry_l1_protection_exit` (and matching horizons/maturities). The web
shows original invalidation, protection, and `SALIDA POR PROTECCION` separately;
open-row distance uses the effective protection level. Independent surviving
Core entries are not swept closed when another entry's last leg exits.

## Contract compatibility and rollout

Optional fields with None defaults: protection_stop, protection_updated_at,
protection_rule_version. Supplied protection requires all three fields.
New terminal enum value: PROTECTION_EXIT. Existing JSON loads unchanged under
the new readers. Old strict readers cannot consume new fields/enum values:
update all opportunity producers/readers together before enabling 7.64.
There is no SQL column migration; the state is held in existing JSON payloads.
Previous engine implementations remain selectable, but rolling back to old
reader code after new events have been written is not wire-compatible.
WSL source/config activation requires the workspace's explicit authorization.
